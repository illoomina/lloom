Clicking Run compiles nothing on your machine — it fetches a pre-compiled wasm module and a quantized LFM2.5-350M checkpoint, then runs our actual engine — the same CPU kernels §2.3.5a validates Metal against — to decode one real token in a Web Worker (killable: the interrupt story evcxr cannot offer). The result is the byte-identical CPU-reference token; the fingerprint below matches the native reference_lfm2 oracle exactly.

Backend: CPU/WASM (no Metal — Metal does not exist in the browser; this is the parity oracle). Weights: quantized GGUF (~219 MB, fetched once). A raw bf16 LFM2 is ~5 GB and does not fit the wasm32 4 GiB ceiling — the quantized path is the real browser story.

// lloom cell — decode one LFM2 token (single-file format, §602)
use lloom::models::quantized_lfm2::ModelWeights;
use lloom_tensor::quantized::{gguf_file, tokenizer::TokenizerFromGguf};
use lloom_tensor::{Device, Tensor};

let content   = gguf_file::Content::read(&mut cursor)?;      // the GGUF
let tokenizer = tokenizers::Tokenizer::from_gguf(&content)?;  // embedded
let ids       = tokenizer.encode(prompt, true)?.get_ids();
let mut model = ModelWeights::from_gguf(content, &mut cursor, &Device::Cpu)?;
let logits    = model.forward(&Tensor::new(ids, &dev)?.unsqueeze(0)?, 0)?;
let next      = argmax(&logits);                              // one real token
idle.
